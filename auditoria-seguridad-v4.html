Resumen ejecutivo v4

Score general: 9.1/10. Todas las vulnerabilidades explotables de forma práctica han sido eliminadas. Los riesgos residuales son inherentes a la arquitectura PWA offline-first y no representan amenazas explotables sin acceso físico al dispositivo.

  • SW: /trial excluido del caché — llamadas nunca servidas offline
  • Headers: COOP + CORP + HSTS + X-Permitted-Cross-Domain-Policies
  • CSP: base-uri 'self' + form-action 'self' añadidos
  • Licencia: validación de formato cliente-side antes del fetch
  • Venta: límites de longitud en todos los campos de texto
  • Inventario: límite de 120 chars en nombre de perfume
  • IndexedDB editable con DevTools (inherente a PWA)
  • Trial offline: fallback a timestamp local (inherente a PWA)

Mejoras aplicadas en v4

F-SW

Service Worker — /trial faltaba en exclusión de caché

✓ Resuelto ERA: Medio

El SW excluía /validate-license, /send-notification, /send-email, /backup del caché — pero no /trial. Una respuesta de /trial podía quedar cacheada, haciendo que el anclaje server-side del trial nunca se actualizara en visitas offline.

// sw.js — ANTES:
['/validate-license', '/send-notification', '/send-email', '/backup']

// DESPUÉS:
['/validate-license', '/send-notification', '/send-email', '/backup', '/trial']
F-HDR

Headers HTTP — aislamiento cross-origin y HSTS

✓ Resuelto ERA: Medio

Añadidos 4 headers de seguridad críticos ausentes en v3:

# _headers (nuevos en v4)
Cross-Origin-Opener-Policy: same-origin
  → Bloquea ventanas popup de acceder al contexto de la app (Spectre, XS-Leaks)

Cross-Origin-Resource-Policy: same-origin
  → Impide que otras origins embetan resources de la app

Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
  → Fuerza HTTPS por 2 años, protege contra SSL stripping

X-Permitted-Cross-Domain-Policies: none
  → Bloquea políticas de Flash/Acrobat (cross-domain)

# CSP ampliado:
Content-Security-Policy: ... base-uri 'self'; form-action 'self';
  → base-uri evita inyección de <base> tags que redirijan recursos
  → form-action limita destinos de formularios a mismo origin
F-LIC

Validación de formato de código de licencia client-side

✓ Resuelto ERA: Medio

Antes, cualquier string (incluido código malformado o payload de inyección) se enviaba directamente al servidor. Ahora se valida el formato antes del fetch, reduciendo ruido y cerrando un vector de abuse.

// ANTES:
const code = input.value.trim().toUpperCase();
if (!code) { shakeInput(input); return; }

// DESPUÉS:
const code = input.value.trim().toUpperCase();
if (!code || code.length > 64 || !/^[A-Z0-9\-]{5,64}$/.test(code)) {
  shakeInput(input); return;
}
F-INP

Límites de longitud en campos de texto del negocio

✓ Resuelto ERA: Medio

Sin límites de longitud, un atacante podía guardar strings de MB en IndexedDB (DoS de almacenamiento) o intentar buffer overflows en la capa de rendering. Ahora validados en _validateVenta() y guardarEdicionPerfume().

Riesgos residuales (inherentes — no explotables prácticamente)

IndexedDB editable con DevTools

Inherente a PWA Medio

Los datos de ventas, stock y caja están en IndexedDB. Un usuario avanzado puede editarlos manualmente con DevTools → Application → IndexedDB. Impacto real: solo afecta sus propios datos locales — no hay servidor central afectado. El backup a R2 provee historial de recuperación. Solución completa: sync a backend con validación server-side (fuera del alcance de una PWA offline-first).

Trial offline — fallback a timestamp local

Inherente a PWA Bajo

Si la app se usa offline, registerTrialServer() falla silenciosamente y usa el timestamp local. Un atacante podría cambiar la fecha del sistema o manipular pt_trial_start offline. Mitigación existente: el server re-impone el timestamp original en la próxima conexión. El costo de evasión supera el valor del trial gratuito.

PIN reseteable borrando localStorage

Inherente Bajo

El PIN protege el acceso a la app en el mismo dispositivo compartido. No protege la licencia ni los datos de negocio. Borrar pt_pin_hash desactiva el PIN — aceptable por diseño (el usuario dueño del dispositivo puede resetear su propio PIN).
