1 · Qué se auditó

Todo ejecutado contra el build real servido, no mocks.

3 · Bugs encontrados

Alta  BUG-01 · La ganancia se sobreestima cuando hay descuento

Impacto: golpea directo la propuesta de valor ("sabé cuánto ganás realmente"). Si el revendedor hace un 20% de descuento sobre $1.000 (cobra $800, pagó $500), el dashboard muestra $500 de ganancia cuando en realidad ganó $300. Con descuentos frecuentes, las ganancias mensuales quedan infladas y el usuario toma decisiones sobre datos falsos.

Causa: renderDashboard() y _renderVentaCard() calculan la ganancia con (v.precioOriginal || v.precioVenta) - v.precioCompra. El comentario // BUG #6 FIX: ganancia bruta lo hizo a propósito, pero es incorrecto para el caso de uso: el vendedor cobró el precio con descuento, no el original.

Reproducir: nueva venta $1.000, compra $500, 20% desc → guardar → dashboard muestra +$500 (debería +$300).

Solución: usar precioVenta (ya con descuento aplicado) para la ganancia. La ganancia "real" es lo que entró menos lo que costó. Revisar también stats y ranking por si comparten el criterio. Dificultad: baja.

Media  BUG-02 · Doble/triple-toque en "Guardar" duplica registros (sistémico)

Impacto: un usuario impaciente o con la señal lenta que toca "Guardar venta" dos veces crea 2–3 ventas idénticas → stock descontado de más, ganancias infladas, cuotas duplicadas. Verificado: 3 toques = 3 ventas. Afecta por igual a venta, gasto, alta de perfume y pedido — ninguno tiene guarda.

Causa: guardarVenta(), guardarGasto(), savePerfume(), guardarPedido() son async sin flag de "guardando" ni deshabilitado del botón durante el await.

Reproducir: llenar venta → tocar "Guardar" 3 veces rápido → aparecen 3 ventas.

Solución: guarda compartida if (this._guardando) return; this._guardando = true; try {…} finally { this._guardando = false; } + deshabilitar el botón mientras corre. Dificultad: baja.

Media  BUG-03 · Datos inyectados sin sanitizar producen totales negativos

Impacto: bajo en uso normal (requiere manipular IndexedDB o un backup adulterado), pero un montoPagado mayor al monto de la cuota deja el total "a cobrar" en negativo (-$9.499). Un import de backup corrupto podría gatillarlo sin malicia.

Causa: al leer cuotas no se acota montoPagado ≤ monto (la escritura sí lo valida desde v1.2, pero los datos viejos/importados no pasan por esa validación).

Solución: normalizar en _fixCuotasSaldadas/lectura: montoPagado = Math.min(montoPagado, monto). También clamp de stock a ≥0 al renderizar. Dificultad: baja.
