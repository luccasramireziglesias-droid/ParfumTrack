🔴 Hallazgos Críticos (5)
Crítico

RC-01: Pagos duplicados por double-tap en cobrarMP/Transferencia/Efectivo

Las 3 funciones de cobro (cobrarMP, cobrarTransferencia, cobrarEfectivo) no tienen ningún guard contra doble clic. Un tap rápido registra el pago 2 veces: 2 entradas en cuotasPagos, 2 en caja, duplicando el monto cobrado. El modal cierra DESPUÉS de la mutación.

index.html:14217, 14241, 14284
Fix: Agregar flag _cobroProcesando + desactivar botones al primer clic.
Crítico

DC-01: Undo de stock usa índice stale del array

findIndex() captura el índice ANTES del filter(). Después del filter, el array es más corto y el índice apunta a la posición equivocada. splice(idx, 0, backup) inserta el perfume en la posición incorrecta. Si era el último item, puede insertar fuera de rango.

index.html:9551, 9558
Fix: Usar push(backup) + re-sort, o capturar snapshot completo del array para undo.
Crítico

EH-01: _saveNow() falla 3 veces sin notificar al usuario — pérdida de datos

Después de 3 fallos consecutivos de escritura a IndexedDB, la función simplemente hace console.error y se rinde. El usuario sigue trabajando creyendo que los datos se guardan, pero nada se persiste. Al recargar, todo se pierde.

index.html:6748-6753
Fix: Agregar toast("Error guardando datos...", 5000, "error") en el bloque de 3 reintentos fallidos.
Crítico

BE-01: CORS headers faltantes en el error handler global (500)

El catch global de worker.js devuelve Content-Type: application/json pero NO incluye Access-Control-Allow-Origin. Cualquier error 500 en cualquier endpoint hace que el browser bloquee la respuesta por CORS, y el frontend no recibe el mensaje de error — solo ve un error opaco de red.

worker.js:27-29
Fix: Agregar corsHeaders(origin) al Response de error 500.
Crítico

BE-02: Token de autenticación expuesto en URL query string (backup/sync GET)

Los endpoints backup y sync GET aceptan ?code=X&token=Y como query params. Los tokens HMAC se loguean en access logs de Cloudflare, en el historial del browser, y pueden ser cacheados por proxies intermedios. Los headers X-PT-Code/X-PT-Token existen pero el fallback a query params permite el leak.

backup.js:98-99, sync.js:112-113
Fix: Eliminar el fallback a query params. Solo aceptar tokens via headers.
🟠 Hallazgos Altos (10)
Alto

RC-02: delMovCaja double-tap corrompe undo

Sin guard contra doble clic. El segundo clic ejecuta con el mismo ID, caja.find() retorna undefined, y el undo captura undefined. Si se hace undo, caja.unshift(undefined) corrompe el array.

index.html:9332-9347
Fix: Agregar if (!mov) return; después del find().
Alto

RC-03: registrarPagoExtra / cobrarDesdePendientes sin guard

Ambas funciones se llaman desde botones inline en la lista de ventas. Sin flag disabled ni processing. Un double-tap pushea el mismo pago 2 veces en cuotasPagos, potencialmente sobrecobrando la venta (calcDebe negativo).

index.html:8871-8902, 8904-8925
Fix: Limpiar el input inmediatamente + flag de procesamiento.
Alto

RC-04: Modal cuota OK — double-click pushea pago duplicado

El botón OK del modal de cuota pushea un pago y luego cierra el modal. En double-click, ambos clics ejecutan antes de que closeModal oculte el modal. El segundo push agrega un pago duplicado.

index.html:8841-8868
Fix: this.disabled = true; como primera línea del onclick.
Alto

RC-05: deleteGasto double-tap + botón compartido

deleteGasto no tiene guard. Además, del-confirm-btn es COMPARTIDO entre openDeleteGastoModal y openDeleteModal (ventas) — ambos rebindean .onclick en el mismo botón. Si se abren ambos modales rápidamente, el último binding gana y se borra la entidad equivocada.

index.html:9856, 10734, 10760
Fix: Separar botones de confirmación por entidad, o agregar _deleteType.
Alto

DC-02: Schema migration — save() no awaited antes de bumpar versión

save(true) llama a _saveNow() sin await. Luego await PTDB.set("pt_schema_version", SCHEMA_VERSION) se ejecuta antes de que los datos migrados se terminen de escribir. Si la app crashea en ese momento, la versión dice "migrado" pero los datos no se persistieron.

index.html:6703-6705
Fix: Cambiar a await _saveNow() cuando immediate es true.
Alto

DC-03: JSON.parse fallido en migración localStorage→IndexedDB pierde datos

Si JSON.parse(raw) falla por datos corruptos, val queda null y la función retorna defaultVal (array vacío). Los datos corruptos quedan en localStorage, pero cualquier acción del usuario dispara save() que escribe [] a IndexedDB. En la próxima carga, PTDB.get(key) retorna [] y la migración nunca se reintenta.

index.html:6662-6681
Fix: Bloquear save() si la migración falló. Notificar al usuario.
Alto

EH-02: 70+ localStorage.setItem sin try/catch — QuotaExceededError

Hay ~70 llamadas a localStorage.setItem sin protección. Cuando storage está lleno, QuotaExceededError crashea la operación en curso. Las peores están en paths críticos: activación de licencia (5 calls), registro trial (4 calls), onboarding (3 calls).

index.html:6490, 7178, 12016-12020, 12445-12453, 14935-14938
Fix: Crear wrapper safeSetItem(key, value) con try/catch. Aplicar en paths críticos.
Alto

BE-03: Rate limit race condition — KV read-then-write no es atómico

checkRateLimit hace GET del contador, incrementa, y PUT. Dos requests concurrentes pueden leer el mismo valor, ambos incrementar a N+1, y el rate limit efectivo permite el doble de requests. Cloudflare KV no tiene operaciones atómicas de incremento.

functions/_shared.js:27-38
Fix: Aceptar como limitación de KV. Para endpoints críticos (trial, pagos), agregar validación adicional server-side.
Alto

BE-04: mp-webhook no verifica currency del pago

El webhook de Mercado Pago procesa el pago sin verificar que currency_id coincida con la configuración (MP_CURRENCY_ID=USD). Un atacante podría crear un pago en una moneda de menor valor y obtener una licencia.

functions/mp-webhook.js:219-224
Fix: Verificar payment.currency_id === env.MP_CURRENCY_ID antes de activar la licencia.
Alto

FE-01: Sanitización de backup restore double-encodes HTML entities

_sanitizeRestored() reemplaza < con &lt; y > con &gt; en TODOS los strings. Si el backup ya contenía entities escapados (ej: &lt;script&gt;), se double-encodean a &amp;lt;script&amp;gt;. Esto corrompe visualmente los datos del usuario.

index.html:7634-7641
Fix: Usar DOMPurify o sanitizar solo al renderizar, no al almacenar.

🏗 Análisis Arquitectónico
Deuda Crítica

Monolito de 19,479 líneas

Todo el frontend vive en un solo archivo HTML: ~3,000 líneas de CSS, ~3,400 de HTML, ~13,000 de JS. Imposible hacer code review parcial, merge conflicts constantes, y cualquier cambio requiere buscar en 19K líneas. No hay módulos, namespaces, ni imports.

Deuda Alta

70+ Variables Globales

Todas las funciones y estados son globales: ventas, perfumes, gastos, caja, metaMensual, flags como _addVentaEnProceso, _backupInFlight, etc. Cualquier función puede mutar cualquier estado sin restricción. No hay encapsulación ni protección.

Deuda Alta

258 Inline Event Handlers

Los eventos se bindean con onclick="funcion()" directo en el HTML, incluyendo HTML generado dinámicamente con innerHTML. Esto impide linting de handlers, hace debugging difícil, y es una fuente principal de los bugs de double-click.

Deuda Media

520 getElementById + 783 Inline Styles

Sin sistema de componentes, cada render función construye HTML como strings con estilos inline. Cambiar un color o padding requiere buscar y cambiar en múltiples lugares. No hay reutilización de componentes UI.

Deuda Media

143 localStorage Directos

Llamadas directas a localStorage.setItem/getItem esparcidas por todo el código sin wrapper centralizado. Esto causa los bugs EH-02 (sin try/catch) y hace imposible migrar a otro storage sin tocar 143 lugares.

Positivo

Backend Bien Estructurado

El backend tiene buena separación: _shared.js centraliza CORS, rate limiting, HMAC, email validation. Cada endpoint es una función independiente. El router en worker.js es limpio. Structured logging implementado. Tests con Vitest.

Roadmap de Refactorización (3 fases)

Fase 1 (1-2 semanas): Extraer CSS a archivo separado, crear safeSetItem wrapper, agregar guards de double-click en todas las funciones de cobro/deleteQuick wins
Fase 2 (3-4 semanas): Modularizar JS con ES modules — separar por dominio: ventas.js, stock.js, caja.js, gastos.js, pagos.js, backup.js, ui.jsArquitectura
Fase 3 (2-3 meses): Migrar a componentes (Lit/vanilla web components), reemplazar innerHTML con DOM API, eliminar variables globales con storesTransformación

🎯 Top 10 Bugs Críticos a Resolver

1. Pagos duplicados por double-tap

RC-01 — Afecta dinero real. Un usuario que toca 2 veces rápido registra el cobro doble. Impacto directo en la confianza y en las finanzas del revendedor.

2. _saveNow silencioso al fallar

EH-01 — El usuario pierde datos sin saberlo. La peor experiencia posible para una app de gestión de ventas.

3. CORS en error 500

BE-01 — Cualquier error de servidor es invisible al frontend. El usuario ve "error de conexión" cuando el servidor respondió, pero CORS bloqueó la respuesta.

4. Token en query string

BE-02 — Tokens de autenticación en URLs se loguean, cachean, y aparecen en historial. Un atacante con acceso a logs puede robar backups de cualquier usuario.

5. Undo stock con índice stale

DC-01 — El perfume se restaura en la posición equivocada. Confunde al usuario y puede causar ventas del producto equivocado si el stock se desordena.

6. Migration save() no awaited

DC-02 — Pérdida silenciosa de datos en el primer uso. Raro pero catastrófico cuando ocurre.

7. mp-webhook sin check de currency

BE-04 — Un atacante puede pagar en moneda de menor valor y obtener licencia. Pérdida de revenue directa.

8. Sanitización double-encode

FE-01 — Los datos del usuario se corrompen visualmente al restaurar un backup. Caracteres especiales se muestran como &lt; en vez de <.

9. localStorage sin try/catch

EH-02 — En 70+ lugares, incluyendo activación de licencia y trial. Si storage está lleno, la operación entera crashea.

10. Migration JSON.parse failure

DC-03 — Si localStorage tiene datos corruptos, la migración falla silenciosamente y el siguiente save() los sobreescribe con arrays vacíos.
