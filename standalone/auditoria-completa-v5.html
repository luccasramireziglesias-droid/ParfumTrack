🔍 Fase 0 — Comprensión del Proyecto

¿Qué es ParfumTrack?

PWA de gestión comercial para revendedores de perfumes en Latinoamérica (Argentina, Uruguay, Colombia, México). Permite registrar ventas (contado/cuotas), controlar stock, calcular ganancia real automática, gestionar cobros vía WhatsApp, generar catálogos visuales, y ver estadísticas detalladas. Funciona offline, sin necesidad de descarga.

Stack y Arquitectura

  • Frontend monolítico: index.html (~19,480 líneas) con CSS + JS inline
  • Backend: 9 Cloudflare Workers Functions (trial, validate-license, backup, sync, send-email, send-notification, mp-create-preference, mp-webhook, mp-payment-status, mp-subscription-status)
  • Router: worker.js como entry point con imports directos
  • Almacenamiento: IndexedDB + localStorage (cliente), KV + R2 (servidor)
  • Pagos: Mercado Pago Checkout Pro con webhook de verificación firmada
  • Emails: Brevo API con templates inline HTML
  • Push: OneSignal Web SDK
  • Analytics: Plausible (sin cookies, GDPR compliant)
  • Deploy: GitHub Actions → Cloudflare Workers con assets

Recursos analizados

  • index.html — ~19,480 líneas (app completa)
  • landing.html — ~2,200 líneas (landing de conversión)
  • worker.js — Router principal (67 líneas)
  • sw.js — Service Worker con caché (97 líneas)
  • 9 funciones backend: trial.js, validate-license.js, send-email.js, send-notification.js, backup.js, sync.js, mp-create-preference.js, mp-webhook.js, mp-payment-status.js, mp-subscription-status.js
  • manifest.json, _headers, wrangler.jsonc
  • Auditoría v4 previa (92/100)

🔒 Fase 2 — Auditoría de Seguridad

Autenticación y Autorización

  • ✓ Licencias: ECDSA P-256 firma servidor → verificación cliente con clave pública embebida
  • ✓ APIs protegidas: HMAC-SHA256 con LICENSE_SERVER_SECRET en backup, sync, send-notification, mp-subscription-status
  • ✓ Trial OTP: código de 6 dígitos vía email, crypto.getRandomValues, 5 intentos máx, 10 min TTL
  • ✓ Timing-safe comparison en todas las verificaciones de token/firma
  • ✓ MP Webhook: verificación de firma x-signature con timestamp anti-replay (±5 min)
  • ✓ mp-payment-status: verifica email contra API de Mercado Pago (no confía en input del usuario)
  • ✓ send-email: anti-relay, verifica que el email esté registrado en KV antes de enviar
  • ✓ Estado seguro (_sec IIFE): flags de activación en closure privada, no accesibles desde DevTools
  • ✓ Date.now capturado antes de que código externo pueda monkey-patchearlo

XSS / Inyección

  • ✓ escapeHTML() aplicada a todos los campos de usuario en innerHTML (nombre, cliente, notas)
  • ✓ send-email.js tiene sanitize() para HTML de contenido de email
  • ✓ Catálogo usa data-attributes + event delegation (evita onclick inline con datos del usuario)
  • ✓ MP checkout valida URL con regex antes de redirect: /^https:\/\/(www|sandbox)\.mercadopago\.com/
  • ✓ send-notification URL sanitizada: solo acepta paths que empiezan con /

Rate Limiting

  • ✓ 9/9 funciones backend con rate limiting KV-based
  • ✓ Todos fail-closed: si PT_LICENSES KV no está configurado → bloquea requests
  • ✓ catch en KV read → retorna error (no deja pasar)
  • ✓ Anti-brute-force: delay 1.5s-2s en intentos fallidos (validate-license, trial verify)
  • ✓ Doble rate limit en trial: por IP + por email
  • ✓ Doble rate limit en send-notification: por IP + por subscriptionId

CORS y Headers de Seguridad

  • ✓ Whitelist de origins consistente en las 9 funciones: localhost, 127.0.0.1, parfumtrack.pages.dev, parfumtrack.luccasramireziglesias.workers.dev
  • ✓ _headers: HSTS (2 años + preload), X-Frame-Options DENY, nosniff, strict referrer
  • ✓ CSP con whitelist explícita de CDNs, sin eval, con self como default
  • ✓ COOP: same-origin-allow-popups (necesario para window.open en MP checkout)
  • ✓ Permissions-Policy: camera, microphone, geolocation y payment deshabilitados

Almacenamiento y Datos

  • ✓ Backup/sync: límite de 5 MB por payload
  • ✓ Código de validación: max 64 caracteres, normalizado toUpperCase
  • ✓ Token format validation: regex /^[0-9a-f]{64}$/
  • ✓ Input length guards en send-notification (subscriptionId 256, title 128, message 512)
  • ✓ Email validation con regex y length ≤ 254
  • ✓ Idempotencia en webhook MP: doble check (event ID + payment ID)

💼 Fase 6 — Startup y Negocio

Propuesta de valor

Clara y bien definida: "Organizá tu negocio de perfumes desde el celular". Resuelve un dolor real (revendedores que usan cuaderno/Excel para controlar ventas, cuotas y stock). El plan Free sin límites elimina la barrera de entrada.

Modelo de monetización

  • Free: Ilimitado (ventas, stock, cuotas, catálogo, offline)
  • Básico Pro: USD 9.99/mes o $95.88/año via Mercado Pago
  • Pro: "Próximamente" (consulta por WhatsApp)

Fortaleza: Free genuinamente útil crea base de usuarios. Conversión vía valor agregado, no paywall agresivo.

Riesgo: Si Free es demasiado completo, la conversión a pago podría ser baja. Necesita features premium diferenciados y claramente comunicados.

Mercado objetivo

Revendedores de perfumes independientes en LATAM. Mercado fragmentado, sin solución dominante especializada. La mayoría usa WhatsApp + cuaderno. Oportunidad real de capturar este nicho con una herramienta gratuita que resuelve sus problemas específicos.

¿Por qué podría fracasar?

  • El target no busca activamente herramientas digitales — depende de marketing viral vía WhatsApp
  • Competencia de apps genéricas de ventas (que ya tienen presupuesto y base de usuarios)
  • Un solo desarrollador — riesgo de bus factor
  • Sin tracción demostrable aún (+340 revendedores citado en landing sin verificar)

🔍 Hallazgos Nuevos v5

Hallazgos detectados en esta auditoría fresca que no estaban cubiertos en v4.

ID Severidad Área Hallazgo Impacto Solución
V5-M01 MEDIO Seguridad worker.js CORS regex no incluye puerto para pages.dev/workers.dev — pero más importante: la regex usa | sin agrupamiento correcto de los puertos. Actualmente el regex de worker.js no limita el puerto a localhost, y el match de parfumtrack.pages.dev no requiere https:// como prefijo. Potencial CORS bypass si un atacante registra un subdominio que termine en el patrón. Actualizar la regex del worker.js para alinearla con las de las funciones individuales (que sí validan correctamente con ^ y $).
V5-M02 MEDIO Técnico worker.js OPTIONS handler no reenvía headers X-PT-Code y X-PT-Token en Allow-Headers. Las funciones backup.js y sync.js leen estos headers pero el preflight centralizado no los incluye. Requests con custom headers desde el navegador podrían fallar el preflight CORS para /backup y /sync si no pasan por query params. Agregar X-PT-Code, X-PT-Token al Access-Control-Allow-Headers en el OPTIONS handler de worker.js.
V5-M03 MEDIO Resiliencia trial.js checkRateLimit no verifica env.PT_LICENSES al inicio — confía en que la comprobación de línea 39 ya lo cubre. Sin embargo, la función checkRateLimit del trial no tiene el bloqueo fail-closed como las demás funciones. Si por alguna razón se alcanzara checkRateLimit con KV faltante, podría dejar pasar requests sin rate limiting. Agregar if (!env.PT_LICENSES) return 'Service temporarily unavailable'; al inicio de checkRateLimit en trial.js.
V5-M04 MEDIO Email trial.js sendOtpEmail no incluye headers List-Unsubscribe como sí tiene send-email.js. Aunque es un email transaccional (OTP), la ausencia podría afectar la reputación del sender con algunos proveedores. Menor deliverability en algunos proveedores de email. Agregar List-Unsubscribe header al email OTP del trial (apuntando a parfumtrack@gmail.com).
V5-L01 BAJO PWA manifest.json tiene "screenshots": [] vacío. Google Play Store y navegadores modernos usan screenshots para mejorar la experiencia de instalación PWA. La experiencia de "instalar app" se ve menos profesional. Agregar 2-3 screenshots del dashboard y ventas al manifest.
V5-L02 BAJO Técnico Monolito index.html con ~19.5K líneas. Funcional pero dificulta mantenimiento. No bloquea launch. Velocidad de desarrollo a largo plazo. Refactor planificado: extraer CSS/JS a archivos separados (roadmap 90 días).
V5-L03 BAJO QA Sin test suite automatizada. Las funciones backend (validate-license, mp-webhook, trial) son candidatas ideales para Vitest + Miniflare. Riesgo de regresiones al modificar código. Implementar tests unitarios con Vitest (roadmap 30 días).
V5-L04 BAJO CDN SRI hashes para Chart.js, jsPDF y XLSX no verificados desde este entorno (CDN bloqueado). Si los hashes son incorrectos, las librerías no cargarán en producción. Funcionalidades de estadísticas, PDF y Excel podrían no funcionar. Verificar en producción que los 3 CDN cargan correctamente.
V5-L05 BAJO UX Modal bulk-remind usa "clienta" en singular femenino (línea 19455). Debería usar lenguaje neutro según instrucciones del proyecto. Inconsistencia de marca. Cambiar "clienta" por "cliente" en el modal de recordatorio masivo.
⚔️ Fase 8 — Análisis Competitivo

Competidores identificados

  • Ventas Pro / Negocio en Mano: Apps genéricas de ventas. Más features pero más complejas. No especializadas en reventa de perfumes.
  • Excel / Google Sheets: El competidor real #1. Gratis, conocido, pero sin automatización de cuotas ni cobros WhatsApp.
  • Cuaderno físico: El competidor real #2. Cero fricción de adopción pero cero automatización.

Ventajas competitivas de ParfumTrack

  • Especialización: Diseñada específicamente para revendedores de perfumes (stock por ml, catálogo visual, cuotas típicas del rubro)
  • WhatsApp nativo: Cobros, catálogo y recordatorios integrados con WA — el canal principal del target
  • PWA offline: Sin descarga, sin internet obligatorio — ideal para zonas con conectividad intermitente
  • Free real: Sin paywall en features core — reduce la barrera de adopción a cero

Como competidor agresivo, atacaría:

  • La dependencia de un solo desarrollador (SPoF humano)
  • La falta de features colaborativas (varios vendedores, jefas de grupo)
  • Datos solo en el dispositivo (sin cuenta cloud obligatoria = pérdida de datos al cambiar celular)
  • Sin API pública ni integraciones con otras herramientas
📊 Fase 9 — Métricas y Crecimiento

Canales de adquisición

  • WhatsApp viral: Firma en mensajes de cobro y catálogos. Tracking con UTM. Canal principal esperado.
  • SEO: Landing optimizada con JSON-LD, FAQ schema. Potencial para búsquedas long-tail ("app para revendedoras de perfumes gratis").
  • Meta Ads: 12 ads planificados cubriendo awareness → consideration → conversion.
  • Plausible Analytics: Configurado para medir sin cookies.

Métrica que destruiría el negocio

Churn por pérdida de datos. Si los usuarios pierden sus datos al cambiar celular o borrar caché, el churn sería masivo y la reputación se destruiría vía boca a boca negativo en los mismos grupos de WhatsApp que son el canal de adquisición. El sync/backup cloud mitiga esto, pero requiere que el usuario active el trial/licencia.
