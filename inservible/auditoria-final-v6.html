Hallazgos CRÍTICOS — todos resueltos

CRÍTICO
Credenciales reales de OneSignal en código fuente
functions/send-notification.js · comentarios de cabecera · ✅ RESUELTO
Los comentarios del archivo contenían ONESIGNAL_APP_ID = "4b037409-ce19-48b9-932c-3021b31b2a33" y ONESIGNAL_REST_KEY = "scaeqmcf7eid4g4uvotnhwfm6" — credenciales reales visibles en el repositorio público.
Fix aplicado: Reemplazados por placeholders genéricos. Las credenciales deben vivir exclusivamente en Cloudflare Pages → Settings → Environment variables.
CRÍTICO
CORS demasiado permisivo (comodines)
worker.js · validate-license.js · backup.js · send-email.js · send-notification.js · ✅ RESUELTO
Las regex de CORS usaban .*\.pages\.dev y .*\.workers\.dev, permitiendo que cualquier subdominio de Cloudflare pudiera hacer peticiones a la API, incluyendo dominios de atacantes.
Fix aplicado: Todos los archivos restringidos a parfumtrack.pages.dev y parfumtrack.workers.dev exactos, más localhost/127.0.0.1 para desarrollo.

Hallazgos ALTOS — todos resueltos

ALTO
XSS en renderVentas — fechas sin escapar
index.html:2219, :2287 · ✅ RESUELTO
ultVenta?.fecha y v.fecha se interpolaban directamente en innerHTML sin pasar por escapeHTML(), permitiendo XSS si una fecha contenía HTML malicioso.
Fix aplicado: Ambos valores ahora se envuelven en escapeHTML().
ALTO
ECDSA private key perdida / sin configurar
Cloudflare env · functions/validate-license.js · ✅ RESUELTO
El Cloudflare dashboard del usuario no tenía configuradas LICENSE_SIGNING_PRIVATE_KEY ni LICENSE_OWNER_CODE. Toda activación de licencia fallaba con 500.
Fix aplicado: Nuevo par de claves ECDSA P-256 generado. Clave pública embebida en index.html (MFkwEw...bA==). Clave privada y código de propietario recuperado (PT-B3FF19-C75C55) para configurar en Cloudflare.
ALTO
Double-submit en stock, caja y backup
index.html · funciones de guardado · ✅ RESUELTO
Las funciones de agregar stock, registrar caja y subir backup podían ejecutarse varias veces simultáneamente si el usuario pulsaba el botón rápidamente, causando duplicados de datos.
Fix aplicado: Guards _addingStock, _addingCaja y _backupInFlight bloquean ejecuciones concurrentes.
ALTO
Brute-force en validate-license (delay insuficiente)
functions/validate-license.js · ✅ RESUELTO
El delay en códigos inválidos era de solo 600ms, insuficiente para frenar ataques de fuerza bruta sistemáticos contra el espacio de licencias.
Fix aplicado: DELAY_ON_INVALID aumentado a 2000ms.

Hallazgos MEDIOS — todos resueltos

MEDIO
renderClientes() O(n²) — reconstrucción de mapa en cada render
index.html · _buildClientesMap() · ✅ RESUELTO
La función iteraba todo el array de ventas en cada llamada a renderClientes(), O(n) por render pero sin memoización, causando degradación progresiva con catálogos grandes.
Fix aplicado: _buildClientesMap() memoizado con _clientesMapCache y flag _clientesMapDirty. Solo se reconstruye cuando save() es llamado.
MEDIO
calcDebe/diasDesdeUltimoPago llamadas 4-6× por cuota
index.html · renderCuotasPendientes() · ✅ RESUELTO
Cada cuota llamaba a calcDebe() y diasDesdeUltimoPago() múltiples veces: durante el sort, durante el render de tarjeta, y durante el render de tooltip.
Fix aplicado: Pre-cómputo via Map antes del sort. _renderCuotaCard() acepta _debe y _dias pre-calculados como parámetros opcionales.
MEDIO
Toast sobreescrito — mensajes perdidos en operaciones rápidas
index.html · función toast() · ✅ RESUELTO
Si se mostraban dos toasts en rápida sucesión, el segundo reemplazaba al primero antes de que el usuario pudiera leerlo.
Fix aplicado: Cola _toastQueue[] que encola toasts mientras uno está visible y los despacha secuencialmente.
MEDIO
Guardar venta habilitado sin datos obligatorios
index.html · formulario de venta · ✅ RESUELTO
El botón "Guardar venta" no se deshabilitaba en tiempo real, permitiendo intentar guardar con perfume o precio vacíos, lo que generaba entradas inválidas en la base de datos.
Fix aplicado: _updateGuardarBtn() valida en oninput de f-perfume y f-pventa. Botón deshabilitado (opacidad 0.45) hasta que ambos campos sean válidos.
MEDIO
Importación acepta precios negativos
index.html · confirmImport() · ✅ RESUELTO
Al importar ventas desde CSV/Excel, no se filtraban filas con precios negativos, que podían corromper estadísticas de ganancia.
Fix aplicado: confirmImport() filtra filas con precioVenta < 0 o precioCompra < 0 y muestra un toast indicando cuántas filas fueron omitidas.
MEDIO
Error de IndexedDB sin feedback al usuario
index.html · _appDataReady · ✅ RESUELTO
Si IndexedDB fallaba al inicializar (cuota excedida, modo privado estricto, etc.), la app se quedaba con el loader girando indefinidamente sin explicar qué ocurrió.
Fix aplicado: Pantalla de error con mensaje específico (QuotaExceededError vs error genérico) y botón "Recargar app".
MEDIO
Debounce ausente en búsqueda de catálogo y preview de foto
index.html · renderCatalogo, regenerarCatalogoCanvas, previewFotoUrl · ✅ RESUELTO
Cada keystroke en el campo de búsqueda disparaba un render completo del catálogo, incluyendo operaciones de canvas costosas.
Fix aplicado: Wrappers debounced: _renderCatalogoD (200ms), _regenerarCatCanvasD (350ms), _previewFotoUrlD (400ms).
MEDIO
Backup con R2 falla silenciosamente
functions/backup.js · ✅ RESUELTO
Si el binding PT_BACKUP de Cloudflare R2 no estaba configurado, el servidor respondía con un error genérico que no quedaba claro en el cliente.
Fix aplicado: Chequeo explícito con respuesta 500 y mensaje "Storage not configured" antes de intentar usar R2.
MEDIO
Validación de email débil en send-email
functions/send-email.js · ✅ RESUELTO
La función aceptaba cualquier string como dirección de email, sin verificar que tuviese un formato básico válido antes de llamar al proveedor de email.
Fix aplicado: Regex de validación /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/ aplicada antes de llamar al servicio de envío.

Hallazgos BAJOS — resueltos en iteración final

BAJO
SW update banner — bug de scope en onclick inline
index.html:6995 · ✅ RESUELTO
El botón "Actualizar" del banner de nueva versión usaba onclick="newSW.postMessage('SKIP_WAITING')" como string inline. Los handlers inline ejecutan en scope global, no en el closure donde newSW está definido — newSW es undefined globalmente, causando un ReferenceError silencioso. El update nunca se aplicaba.
Fix aplicado: Botón con id="sw-update-btn" sin onclick. Listener agregado vía addEventListener('click', () => newSW.postMessage('SKIP_WAITING')) que captura newSW por closure.
BAJO
.pca-btn tap target por debajo de 44px
index.html:390 · CSS .pca-btn · ✅ RESUELTO
La clase .pca-btn (botones Editar/Eliminar de tarjetas de perfume) tenía min-height:unset;min-width:unset; que sobreescribía explícitamente la regla global de 44px mínimo, dejando los botones por debajo del estándar de accesibilidad táctil de Apple/Google.
Fix aplicado: Eliminados min-height:unset y min-width:unset. Se establece min-height:44px explícito.

Arquitectura de seguridad — estado final

OK
Verificación de licencias ECDSA P-256 (client-side)
index.html · LICENSE_VERIFY_KEY_B64
La clave pública ECDSA está embebida en el cliente. El servidor firma cada activación exitosa. El cliente verifica la firma con crypto.subtle.verify() antes de desbloquear funcionalidades. Sin conexión al servidor no se puede fabricar una firma válida.
OK
HMAC-SHA256 para autenticación de backup
functions/backup.js · timingSafeEqual()
El token de backup se verifica con comparación en tiempo constante (timingSafeEqual()) para prevenir timing attacks. El token es HMAC-SHA256 del código de licencia con el secreto del servidor.
OK
Service Worker — Network First + PWA correcta
sw.js v5
HTML siempre se sirve desde red (Network First). Assets estáticos usan Cache First. APIs nunca se cachean. OneSignal importScript en try/catch para no bloquear el SW si falla. Actualización de versión via banner con postMessage.
OK
escapeHTML() aplicado consistentemente
index.html · toda interpolación de datos de usuario en innerHTML
Todos los puntos de interpolación de datos en innerHTML pasan por escapeHTML(). Se verificaron específicamente: nombres de perfume, nombres de cliente, notas, fechas, y cualquier dato que provenga de IndexedDB o de input del usuario.
