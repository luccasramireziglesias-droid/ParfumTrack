🔴 CRÍTICO de negocio: Toda la lógica de licencia vive en localStorage:

Catálogo Completo de Bugs
QA Lead · Security Engineer · Frontend Senior
🔴 Críticos
SEC-01 Licencia bypasseable via localStorage NUEVO CRÍTICO

Reproducción: DevTools → Application → Local Storage → setear pt_activated_code a cualquier valor → recargar.

Causa raíz: isActivated() solo verifica !!localStorage.getItem('pt_activated_code'). No hay re-validación server-side después de la activación inicial.

Impacto: Pérdida total de ingresos. Cualquier usuario técnico accede gratis permanentemente.

Fix: Periodic re-validation: al cargar la app, si hay un código en localStorage, validar contra el servidor cada N horas (hash + timestamp). Si falla, marcar como inválido.

SEC-02 Trial permanente via localStorage NUEVO CRÍTICO

Reproducción: localStorage.setItem('pt_trial_start', Date.now()) cada vez que el trial expire → trial infinito.

O aún más simple: localStorage.removeItem('pt_trial_start') → el trial nunca arranca → acceso sin restricciones.

Causa raíz: El trial start está almacenado client-side sin ninguna validación server-side.

Fix: Usar el Worker para emitir un token firmado con timestamp al primer acceso. Almacenarlo en localStorage pero validar la firma en cada carga. Sin firma válida, el trial no existe.

DEPLOY-01 Build fallando en producción — app no actualizada NUEVO CRÍTICO

Reproducción: Dashboard Cloudflare → parfumtrack → "Latest build failed".

Causa raíz: wrangler.jsonc declara un R2 bucket binding (PT_BACKUP: "parfumtrack-backups") pero el bucket nunca fue creado. Cloudflare rechaza el deploy.

Impacto: Todos los 22 fixes de seguridad y funcionalidad de esta sesión no están en producción. Los usuarios reales siguen usando la versión vulnerable.

Fix inmediato: Crear bucket parfumtrack-backups en Cloudflare R2 → el siguiente push triggerea el build automáticamente.

🟠 Altos
XSS-01 p.fecha sin escapeHTML en cuotas panel (stored XSS via backup) NUEVO ALTO

Afecta: cuotas panel (~línea 2508), renderCaja (${m.fecha}), renderGastos (${c.fecha}), fechas estimadas (${_fe}).

Vector: Un backup malicioso con fecha: "01/01/2026<script>...</script>" se inyecta al importar.

Fix: Envolver todos en escapeHTML(p.fecha), escapeHTML(m.fecha), etc.

XSS-02 LICENSE.clientName sin escapeHTML en renderAjustes NUEVO ALTO

Código vulnerable (~línea 4068):

html += `<div>👤 Perfil: <strong ...>${LICENSE.clientName}</strong></div>`;

LICENSE.clientName viene del servidor al validar el código. Si el nombre de un cliente contiene HTML (Juan<img src=x onerror=alert(1)>), se inyecta en el innerHTML de ajustes.

Fix: escapeHTML(LICENSE.clientName)

BUG-SW Service Worker sw.js no auditado — posible cache stale PENDIENTE ALTO

El service worker en /sw.js se registra pero nunca fue auditado. Riesgos:

1. Cache agresivo → usuarios reciben versiones antiguas post-deploy, sin los fixes de seguridad.

2. Sin versioning → si el SW no invalida la cache, todos los 22 fixes son invisibles para usuarios con app instalada.

3. Si el SW intercepta requests al Worker API, podría cachear respuestas de validación de licencia.

BUG-13 PIN hash almacenado en localStorage — brute-forceable offline PENDIENTE ALTO

El hash SHA-256 del PIN se guarda en localStorage.getItem('pt_pin_hash'). Cualquier acceso físico al dispositivo + DevTools permite extraer el hash y hacer brute force offline de PINs de 4 dígitos (solo 10.000 combinaciones, en segundos).

Fix: Almacenar el hash en IndexedDB (menos accesible que localStorage). Agregar salt único por dispositivo. El lockout (_failsMem) es solo en memoria — se resetea al recargar.

BUG-14 Descuento 100% → precio final $0 → se acepta como venta NUEVO ALTO

Reproducción: Agregar venta con descuento 100% → se guarda con precio $0 y ganancia negativa (igual a -precioCompra).

Impacto: Estadísticas distorsionadas. Venta registrada con precio $0 es inconsistente con cualquier reporte.

Fix:

if(dto === 100){ _abort('⚠ Un descuento del 100% equivale a dar el producto gratis. Confirmá.'); return; }

¿Qué se degrada primero en mobile económico?

1. renderGanancias() + Chart.js: La combinación de reducir todos los meses + renderizar Chart.js en cada cambio de tab puede causar jank visible en devices con <2GB RAM. Solución: memoizar por mesKey.

2. Exportar PDF con fotos: Cargar 10+ imágenes en canvas simultáneamente puede freezear el hilo principal 2-8 segundos en mobile económico.

3. IndexedDB serialize con 1000+ ventas: JSON.stringify(ventas) en el main thread. Solución: Web Worker para serialización.

4. Monolito de 7.009 líneas: Parse inicial ~40-80ms en V8, <200ms en JavascriptCore (iOS). No crítico pero nota para futuro.

Deuda técnica principal (por impacto)

1. Monolito de 7.009 líneas — todo el JS en un archivo. Imposible tree-shaking, code splitting, o testing unitario real.

2. Licencias en localStorage — no escala a ninguna cantidad de usuarios. Necesita servidor con BD.

3. Sin sistema de logging — cuando algo falla en producción, no hay forma de saberlo sin que el usuario lo reporte.

4. Sin versioning de datos — si se cambia el schema de ventas, los backups viejos pueden fallar silenciosamente.
