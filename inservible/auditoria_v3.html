Seguridad — Análisis completo
✅
Secretos movidos al servidor RESUELTO
Antes: const _LK = 'PT_LICENSE_SECRET_K3Y_2026' expuesto en el cliente. Ahora: todo vive en LICENSE_SERVER_SECRET como env var de Netlify. El cliente nunca ve el secreto.
✅
Token server-side con HMAC-SHA256 RESUELTO
El token es HMAC-SHA256(code:activatedAt, secret). Unforgeable sin el secreto del servidor. Verificación con crypto.timingSafeEqual() — resiste timing attacks.
token = HMAC-SHA256(`${code}:${activatedAt}`, LICENSE_SERVER_SECRET)
✅
Revocación de licencias vía env var RESUELTO
Quitar un código de VALID_LICENSE_CODES y hacer redeploy lo revoca. La app detecta la revocación en la próxima verificación (≤7 días) y limpia el token.
✅
CORS restringido a dominio Netlify RESUELTO
Las Functions solo aceptan Origin que match *.netlify.app o localhost. Cualquier otro origin recibe Access-Control-Allow-Origin: null.
✅
XSS eliminado en renderizado de datos RESUELTO
escapeHTML() aplicado a todos los campos de usuario que se insertan via innerHTML: perfume, vendedor, cliente, nota, proveedor, descripción caja.
✅
CSP actualizada con nuevos dominios RESUELTO
fonts.bunny.net en style-src y font-src. plausible.io en script-src y connect-src. *.netlify.app en connect-src.
script-src 'self' 'unsafe-inline' cdnjs.cloudflare.com plausible.io
⚠️
'unsafe-inline' en CSP PENDIENTE
Necesario porque todo el JS está inline en el HTML. La solución correcta es separar el JS en archivos externos (tarea pendiente de modularización). Sin eso, un nonce por request sería la alternativa.
🐛
Bug corregido: const err duplicado en activarLicencia() CORREGIDO HOY
En el bloque else de la validación de código incorrecto, la variable err estaba declarada dos veces con const. En modo estricto o entornos modernos esto lanza un SyntaxError que rompería el flujo de activación.
// ANTES (bug): const err = document.getElementById('activation-error'); const err = document.getElementById('activation-error'); // ← duplicado // DESPUÉS (corregido): const err = document.getElementById('activation-error');
🛡
Anti-brute-force en validate-license RESUELTO
La Function introduce un delay de 600ms en respuestas inválidas para dificultar ataques de fuerza bruta sobre el endpoint de validación.

Performance & Arquitectura
✅
Service Worker v4 — estrategia CDN correcta RESUELTO
Cache-First para Chart.js, jsPDF, SheetJS (instala en primer uso, sirve offline). Network-First para navegación HTML (siempre la versión más nueva). Cache-First para assets estáticos (íconos, manifest).
✅
Compresión gzip habilitada en Netlify RESUELTO
skip_processing = false en netlify.toml. El HTML de ~311KB comprime a ~90KB en tránsito. Reducción del 71% en el primer cargado.
⚠️
JS monolítico — 311KB, 198 funciones en un solo archivo DEUDA TÉCNICA
Todo el JavaScript está embebido inline en index.html. Esto impide que el navegador cachee el JS separadamente del HTML. Cada deploy invalida el caché aunque el JS no haya cambiado. La tarea de modularización (separar en archivos .js externos) mejoraría significativamente el tiempo de carga en visitas recurrentes.
✅
IndexedDB con debounce — escrituras optimizadas OK
El wrapper PTDB agrupa las escrituras con un debounce de 500ms. En escenarios de edición rápida, evita múltiples escrituras simultáneas a IndexedDB.
✅
Cache-Control correcto por tipo de recurso OK
manifest.json: 24h. íconos PNG: 30 días. sw.js: no-cache, no-store (siempre fresco). HTML: Network-First via SW.
